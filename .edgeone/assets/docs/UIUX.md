# TitleLab·爆款标题实验室 — UIUX 设计文档

> 生成日期：2026-10-09 | 设计师：颜好看（mvp-dev-expert-team-designer）
> 输入：用户 3 句核心需求 + 已知审美偏好（暖纸背景 / 深绿主色 / 大圆角卡片 / 滚动渐显克制风）
> 三轴刻度：**Variance = 5**（工具型产品，轻微非对称即可） / **Motion = 3**（用户明确要求克制） / **Density = 4**（日常应用模式）
> 寄存器判定：**Product 寄存器**（设计服务工具流程），但首屏承担 Brand 职能（直接呈现核心功能即最佳品牌表达）

## 1. 竞品 UI 调研（3 个对标 + 设计短板）

### 1.1 千瓜数据（qian-gua.com）/ 新红（xh.newrank.cn）—— 小红书数据平台双雄

**界面模式**：经典 B2B 数据后台——左侧多级导航（达人/笔记/品牌/直播/大盘 20+ 入口）+ 顶部搜索 + 数据表格与排行榜为主体；小红书品牌红做点缀色；新红的「标题生成」「关键词 PK」「违禁词查询」等创作者工具被埋在三级菜单里，且需注册登录、会员付费才能使用。

**设计短板（我们要利用的差异化机会）**：
1. **功能入口深**：个人创作者想「测一个标题」需要注册 → 找到工具入口 → 付费，路径远超任务本身；TitleLab 反其道——首屏即输入框，零登录、零上传。
2. **数据后台审美与创作者气质脱节**：表格 + 筛选器 + 密集数字是给 MCN 运营看的，不是给写笔记的创作者看的；创作者的语境是「手账、灵感本」，不是「报表」。
3. **只给数据不给判断**：给你热词榜、爆文榜，但「我这个标题行不行」仍要自己推理；没有即时评分—诊断—改写的闭环。
4. **无移动端优先**：移动端是数据平台的二等公民，而小红书创作者 80% 场景在手机上。

### 1.2 CoSchedule Headline Analyzer（Headline Analyzer Studio）

**界面模式**：输入框 → 0-100 Headline Score（红黄绿色带）+ SEO Score 双分 → Word Balance（常见词/不常见词/情绪词/力量词占比条）→ 长度/字符/情绪/可读性分项 → Google/邮件预览 → 历史版本对比。WordPress 插件形态在编辑器侧栏常驻。

**设计短板**：
1. **英语博客/SEO 语境，概念无法平移**：「Common/Uncommon words」的词频库、SERP 60 字符截断规则对中文小红书完全失效；小红书的真实约束是**双行约 20 字显示上限 + 封面图协同 + 正文首句承接**，没有竞品在做。
2. **表单留资门槛**：免费版需提交姓名邮箱；对「快速测一下」的场景是致命摩擦。
3. **只诊断不生产**：给出「加情绪词」的建议，但不直接给你改好的标题；用户仍要自己改写再回来重测，迭代回路断裂。
4. **视觉为企业营销风**（橙蓝 SaaS 模板），结果页是长报表，移动端适配弱。

### 1.3 Sharethrough Headline Analyzer

**界面模式**：公认三者中界面最干净——单输入框 → Headline Quality Score + **Engagement / Impression 双子分** → Strengths（做对了什么，绿色勾列表）→ Suggestions（改进建议）→ 词典热力提示（Context Words 高亮）。无注册即可用。

**可借鉴的模式（我们吸收）**：
- 「总分 + 双子分」结构 → TitleLab 用「爆款指数 + 打开吸引力 / 搜索友好度」双分。
- **Strengths 先于 Weaknesses**：先告诉用户哪里做对了（正反馈留存），再说哪里要改——这个顺序对创作者心态极其重要，照搬。
- 建议直接挂在具体词上（高亮那个词），而不是抽象说「加强情绪」。

**设计短板**：
1. 同样是英文广告文案语境，无中文分词/热词能力，无平台规则。
2. **无 A/B 对比与历史轨迹的视觉化**（历史只是文字列表）。
3. 结果是一次性快照，无「改写 → 重测 → 提升」的游戏化闭环。

### 1.4 竞品调研结论

| 维度 | 千瓜/新红 | CoSchedule | Sharethrough | **TitleLab 策略** |
|---|---|---|---|---|
| 即时可用 | ✗ 登录付费 | ✗ 留资 | ✓ | ✓ 零登录零上传，首屏即输入 |
| 中文/小红书语境 | ✓ 但面向机构 | ✗ | ✗ | ✓ 原生（20 字约束/赛道/热词） |
| 诊断→改写闭环 | ✗ | ✗ 只诊断 | ✗ | ✓ 评分→诊断→变体→A/B 全闭环 |
| 审美气质 | 数据后台 | 企业 SaaS | 干净但无个性 | 暖纸+深绿「创作手账/实验室」 |
| 移动端 | 弱 | 弱 | 中 | **移动端优先** |

## 2. 对标品牌与设计语言结论

### 2.1 设计概念：「植物标本馆 × 创作实验手账」

用户偏好（暖纸 + 深绿 + 大圆角 + 克制渐显）经过专业提炼，落为一个统一隐喻——**「实验记录本」**：

- **暖纸背景 = 实验记录纸**：不是 AI 默认的奶油色底，而是带明显暖调、有纤维感的纸色（`#F6F1E6`，色相 ~46°、比通用米色更深一档），配合深绿墨水文字，读作「本子」而非「模板背景」。
- **深绿 = 墨水与标本**：`#1D5C3F` 深绿既是品牌主色也是「墨水色」，标题里的高亮词用「标本标签」式的绿色浅底（`--accent-soft`）标记——诊断可视化直接借用手账的视觉语言（下划线、圈注、标签贴纸），而不是仪表盘的进度环。
- **大圆角 = 纸片的柔软边缘**：卡片圆角 16px、主仪器卡 20px，克制在「软纸片」感知范围内，不做泡泡糖式的 24px+。
- **滚动渐显 = 翻页**：区块以 12px 上移 + 淡入进入（250ms ease-out），像翻动纸页，绝无弹跳。

**为什么不走编辑杂志风**：暖纸 + 衬线 + mono 小标签是当下 AI 工具的默认「文艺模板」，已被用滥。本方案刻意回避「衬线大标题 + 斜体 + 分隔线」三件套，改用**楷体系展示字体**（霞鹜文楷）——楷体是小红书创作者亲手写笔记时最熟悉的字形，与产品语境天然咬合，且在 Web 产品中极少见，一眼不是 AI 模板。

### 2.2 对标品牌

| 品牌 | 借鉴点 |
|---|---|
| **Bear / Flomo**（笔记应用） | 暖色纸面 + 极简工具流程 + 克制动效的成熟范式 |
| **Headspace** | 大圆角 + 有机形态 + 高饱和点缀色如何不失控 |
| **Sharethrough** | 结果页信息架构（总分/双分/Strengths 优先） |
| 反对标：Stripe/Linear 的冷感科技风 | 明确不采用——与创作者人群气质错位 |

### 2.3 三条硬边界（对用户偏好的专业修正）

1. **暖纸不做「奶油默认」**：纸色加深到 `#F6F1E6` 并叠加强调色绿与楷体字重，确保第一感知是「有意识的手账设计」而非「AI 默认米色」。
2. **圆角上限 20px**：满足「大圆角」感知，同时守住卡片 ≤16-20px 的工艺红线，避免过度圆润的塑料感。
3. **动效全站 ≤ 250ms（唯二例外见 §6）**：用户要「克制的滚动渐显」，全站统一 200-250ms ease-out，禁止任何回弹/弹跳曲线。

  --motion-slow: 250ms;    /* 滚动渐显/抽屉 */

**每屏强调色 ≤2 处的执行口径**：深绿 `--accent` 只允许出现在 ①主 CTA（开始检测/一键优化）与 ②评分结果中「爆款档」的数字/徽章。维度条、chips、链接一律用中性色与语义色带，不得滥用绿。

## 4. 页面结构 Wireframe（单页滚动，自上而下）

> 信息层级总原则：**输入 → 结果 → 诊断 → 改写 → 对比** 是一条向下的「实验流程线」，滚动方向即工作流方向，用户不需要返回顶部（每次重测在结果卡内完成）。

### 4.1 顶部导航（sticky，高 56px，纸色 92% 不透明 + 1px 底边框）
- 左：产品标识「TitleLab·爆款标题实验室」+ 烧瓶 logo 图标（24px）
- 中（桌面）：锚点导航「如何工作 / 模型说明 / 定价」（滚动淡入后出现，首屏聚焦输入不干扰）
- 右：模型状态徽章（「本地模型已就绪」绿点 / 「训练中…」琥珀点）+ 历史记录按钮（图标 24px + 44×44 热区）
- 移动端：仅 logo + 状态徽章 + 历史图标

### 4.2 首屏 Hero = 输入区（Brand 寄存器职责：直接展示核心功能）
- **不做**大标题+口号+抽象图形的模板 Hero。布局为轻微非对称（Variance=5）：左侧 60% 为主仪器卡，右侧 40% 桌面端放「三步流程」竖排小卡（①粘贴标题 → ②看分诊断 → ③一键改写），移动端折叠到下方。
- 主仪器卡（`--surface`、`--radius-xl`、`--shadow-md` + 1px 边框，内边距 32px）：
  - 卡顶小字（`--text-sm` `--muted`）：「粘贴你的笔记标题，本地模型 3 秒给出爆款指数」——一句话讲清价值与隐私。
  - 标题输入框：**大号楷体输入**（`--font-display`，18px，`--radius-md`，`--surface-warm` 底），min-height 88px（两行），placeholder 为真实语感示例：「秋天第一杯奶茶，我劝你先看完这篇」。
  - 输入框下缘实时字数计数（mono 字体）：`12 / 20 字`，**超 20 字变 `--warn` 并提示「首屏双行仅显示约 20 字，超出部分将被折叠」**——这是竞品都没有的平台规则内化。
  - 赛道选择 chips（横向滚动胶囊，`--radius-full`）：美妆 / 穿搭 / 家居 / 美食 / 职场 / 学习 / 旅行 / 母婴 / 通用。选中态 = `--accent-soft` 底 + `--accent` 字（第 2 处绿色的例外：选中态属交互反馈，非装饰）。
  - 主 CTA：「开始检测」（`--accent` 底、`--accent-on` 字、`--radius-md`、高 48px、scan-search 图标 20px）。旁列 Ghost 按钮「试试示例」（随机填充一条真实风格示例标题，降低冷启动门槛）。
  - 卡底小字：shield-off/锁 图标 16px +「标题只在本机处理，不上传、不留痕」。
- 首屏滚动渐显：导航静态；仪器卡以 16px 上移淡入（250ms ease-out）一次性进入，之后不再动。

### 4.3 模型训练反馈条（首次访问，条件渲染）
- 首次触发检测时，在仪器卡下方展开一条训练进度卡（高 64px，`--radius-lg`）：
  - 左：brain 图标 + 当前阶段文案（逐段切换）：「加载热词库 5,214 条」→「构建标题特征」→「本地训练 epoch 12/20」→「模型就绪，开始检测」。
  - 中：细进度条（6px 高，`--score-track` 底 + `--accent` 填充，宽度过渡 200ms）。
  - 右：百分比数字（mono）。
- 训练完成后此卡收起为导航栏的状态徽章，二次检测不再出现（进度条期间 CTA 置 disabled + spinner 图标）。

### 4.4 评分结果卡（检测完成后渐显展开，页面核心焦点）
- 卡片 `--radius-xl` + `--shadow-lg`（全页唯一用 lg 阴影处，制造「报告纸片」的重量感）。
- 左侧：**爆款指数大数字**（`--text-score` 楷体，颜色按分数段取 `--score-*` token）+ 等级徽章（「爆款潜质 / 良好 / 普通 / 待优化」，胶囊，语义色描边不填充）。数字从 0 滚动至终值（500ms，见 §6.3）。
- 右侧两列小数据（mono 数值 + 楷体标签）：
  - 双子分：打开吸引力 `76` / 搜索友好度 `58`（Sharethrough 双分结构的中文落地）
  - 同赛道分位：超过 `63%` 的「美食」赛道标题
- 卡底一行 Strengths（**先说做对的**）：「具体数字 ✓ · 有场景词 ✓」，绿色小勾图标 16px，最多 3 条。
- 卡内右上角 Ghost 按钮「重新检测」——**改写迭代不离开此卡**，重测即地刷新数字（300ms 内完成，无整页滚动）。

### 4.5 维度诊断条（紧随评分卡，同属「报告」视觉组）
- 六个维度，每行结构：`维度名（楷体 16px） + 得分（mono） + 水平条 + 一句诊断 + 建议动作`：
  1. 情绪浓度（heart-pulse 图标）
  2. 具体度·数字感（hash）
  3. 长度适配（ruler/type）
  4. 热词命中（flame→改用 search-star 语义）
  5. 悬念与好奇（eye）
  6. 平台语感（message-circle）
- 水平条：高 8px、`--radius-full`、底轨 `--score-track`、填充色按该维度分数取评分色带 token；**条内不做渐变**，纯色填充。
- 诊断文案直接指向词：「『劝你』是高情绪词，保留；缺少数字——加一个具体数字（如天数/价格/次数）通常提升打开率」。
- 标题原文以楷体重展示在组顶部，**命中词用 `--accent-soft` 底色圈注**（标本标签隐喻的落地：像老师在本子上划重点）。

### 4.6 优化变体卡（「一键优化」CTA 触发后渐显）
- 顶部：主 CTA「一键优化改写」（sparkles 图标）+ 说明「基于诊断短板生成 3 个改写方向」。
- 三张变体卡（`--radius-lg`，桌面三列、移动纵向堆叠）：
  - 策略标签（胶囊）：「+具体数字」「+情绪钩子」「换悬念句式」
  - 变体标题（楷体 18px，**改动处用 `--accent-soft` 高亮**，与 §4.5 圈注语言一致）
  - 各自预估分（小号数字 + 相对原题的 `+12` 提升，`--success` 色）
  - 每卡两个动作：「复制」（copy 图标）与「送去对比」（compare 图标，Ghost 按钮）
- 变体生成期间：卡片骨架屏（`--surface-warm` 底 + 标题行灰条），600ms 内逐卡 stagger 60ms 渐显——训练感被翻译成「逐条写出」的手感。

### 4.7 A/B 对比区（选中变体后渐显）
- 左右两栏（移动端上下堆叠）：「原题」vs「 challenger 变体」，各自显示总分 + 六维度**双向条形图**（中轴向左右延伸，一眼看出哪边长）。
- 胜出方卡片边框换 `--score-viral` 1.5px + 「领先 4 维」小徽章——用边框与徽章表达胜负，不用发光。
- 底部动作：「采用变体并复制」（主 CTA）/「都不够好，换个方向重写」（Ghost，回到 §4.6 再生成）。

### 4.8 模型透明度面板（信任建设，默认折叠 `<details>`）
- 「这个分数怎么来的？」楷体小标题，展开后：
  - 特征权重条形列表（scale 图标）：六个维度的模型权重（mono 数值），注明「权重由 2,140 条高互动笔记训练得出，本地浏览器内运行」。
  - 局限性声明确文案（诚实是小红书语境的稀缺品）：「评分是概率参考，不保证爆款；最终打开率还取决于封面与正文首句。」
- 此区不渐显动画，保持文档的安静感。

### 4.9 定价区（`--bg-deep` 交替底色分区）
- 两档（认知负荷 ≤4：两档优于三档）：
  - **免费 · 本地版**：无限次检测、6 维诊断、3 个改写变体——「你现在用的就是」，当前态徽章。
  - **Pro · 云端版**：¥19/月——更大云端模型、批量测 50 条、导出报表、赛道热词周报。CTA「加入候补」。
- 定价数字用楷体大号；功能对照用两列清单（check 图标 16px），不用三列等宽卡片网格（避免 AI 模板味），Pro 卡略宽（6:5 非对称）。

### 4.10 页脚
- 一行式：logo 小字 + 「纯前端开源 · 数据不出浏览器」+ GitHub / 关于 / 隐私说明（三点链接）+ © 2026。
- 深绿墨水色细字（`--muted`），高 96px，安静收尾。

### 4.11 滚动渐显节奏（全站统一规范）
- 触发：IntersectionObserver，进入视口 15% 即触发，仅触发一次。
- 动画：`opacity 0→1` + `translateY 12px→0`，250ms `--ease-out`；同组子元素 stagger 60ms。
- 首屏（4.2）不参与滚动渐显（加载即在场）；4.4-4.7 的结果区用「展开式渐显」（检测结果生成后才挂载，配合 200ms 进入），不与滚动混淆。
- `prefers-reduced-motion: reduce` 时全部改为纯 opacity 120ms 或直接呈现。

## 6. 交互细节

### 6.1 加载态：本地模型训练（首次）
- 顺序反馈（见 §4.3）：阶段文案 + 进度条 + 百分比，文案具体到数字（「热词库 5,214 条」），让等待可感知为「仪器在标定」。
- 期间主 CTA：disabled + `spinner` 图标替换 scan-search，文字改「正在就绪…」，禁止重复提交。
- Edge：训练失败（极旧浏览器无 WASM）→ 结果区显示 `alert-note` + 具体错误（「当前浏览器不支持本地训练，请改用 Chrome/Edge/Safari 最新版」）+ 「重试」按钮，绝不暴露技术堆栈细节。

### 6.2 空态
- 历史抽屉空态：「还没有检测记录——你的第一条爆款标题从上面开始」（`history` 图标 24px + 引导按钮「去检测」跳回仪器卡）。
- 对比区空态（未选变体时）：不渲染整区，仅在变体卡上有入口，避免空区块。

### 6.3 评分数字滚动
- 数字从 0 → 终值，**500ms**（全站唯二超 250ms 的动画之一，理由：滚动是「计算完成」的语义反馈，快于 400ms 感知不到过程；缓动 `--ease-out`，无回弹无过冲）。
- 伴随大数字色值从 `--muted` 过渡到对应分档色（200ms，在滚动后半段触发）。
- `prefers-reduced-motion`：直接呈现终值。

### 6.4 维度条填充
- 结果渐显后 100ms 开始，逐条 stagger 60ms，每条宽度 0→值（300ms ease-out——第二处超 250ms 例外，同样有数据语义理由）。
- 悬停某维度行：整行 `--surface-warm` 底（150ms），诊断文案展开完整版（默认一行截断）。

### 6.5 复制反馈
- 点击复制：`copy` 图标 → `check` 图标（150ms 交叉淡入），按钮旁 tooltip「已复制」，1200ms 后还原；不弹全局 toast（打断感强）。
- 「采用变体并复制」成功才用右下角 toast（`check-circle` + 「已复制到剪贴板」），240ms 滑入。

### 6.6 历史记录
- localStorage 存储（标题/赛道/分数/时间戳，上限 50 条）。
- 桌面：右侧抽屉（360px，250ms 滑入，遮罩 `rgba(31,42,35,0.32)`）；移动端：底部 ActionSheet（圆角顶部 20px，下滑关闭）。
- 条目：楷体标题一行截断 + 分数色点 + 相对时间（「8 分钟前」）；点击 → 回填仪器卡并自动重测；`trash` 删除单条（二次确认用行内「确认删除？」而非弹窗）。
- 键盘可达：抽屉内 Tab 循环，Esc 关闭。

## 7. 响应式策略（移动端优先）

小红书创作者以手机为主力设备，**所有区块先设计 375px 宽，再向上增强**。

| 断点 | 布局行为 |
|---|---|
| <640px（主战场） | 单列；仪器卡内边距 32→20px；首屏非对称右栏流程卡折叠到仪器卡下方横排三小步；维度诊断/变体卡纵向堆叠；A/B 对比上下堆叠（原题在上）；历史用底部 ActionSheet；导航仅 logo+状态+历史 |
| 640-1024px | 两列萌芽：变体三卡 → 2+1；A/B 左右两栏恢复 |
| ≥1024px | 完整布局：首屏 60/40 非对称；变体三列；定价 6:5 两卡 |
| ≥1280px | 容器封顶 `--container-max: 1080px`，两侧留白渐增（不做满屏拉伸） |

- 触摸目标：所有可点元素 ≥44×44px（chips 高 36px 但整行可滚 + 间距 8px，按钮统一高 48px）。
- 输入：`textarea` 关闭自动大写；检测按钮在移动端吸附于仪器卡底部（不全局 sticky，避免遮挡结果区）。
- 性能：楷体 webfont 子集化（仅常用 3500 字 + 数字标点，woff2 ≤ 800KB；display=swap，先落 Noto Serif SC 再换文楷）；模型 WASM 懒加载，首屏 JS ≤ 200KB。
- 无障碍兜底：全站 `--muted` 以上文本对比度 ≥4.5:1（已按 `#6A7365` on `#F6F1E6` 校准）；`:focus-visible` 用 `--focus-ring`；色彩分档永远同时有文字标签（「普通」），不裸靠颜色传达。

## 8. Do's & Don'ts（给前端的红线清单）

**Do**
- 每屏绿色可见使用 ≤2 处（主 CTA + 评分爆款档），其余用中性纸色系。
- 诊断语言=手账圈注语言：高亮词用 `--accent-soft` 底 + 深绿字。
- 所有真实示例文案用真实创作者语感（「月薪 3k 也能抄的 12 套通勤穿搭」），禁 Lorem/Welcome。
- 动效全部走 `--ease-out`，唯一两个 >250ms 动画必须带数据语义（评分滚动/维度填充）。
- 纸面纹理可选叠加 ≤3% 透明度的噪点 SVG，性能允许时启用，禁用任何大面积渐变。

**Don't**
- 禁紫色→粉色渐变、Indigo→Pink 组合（P0）。
- 禁 emoji 作 UI 功能图标（用户标题内容里的 emoji 属 UGC，正常显示）。
- 禁 `cubic-bezier` 回弹曲线、>1s 动画、同时 3+ 元素各自动画。
- 禁卡片圆角 >20px、边框+大阴影同用的「幽灵卡片」、彩色左侧条纹边框。
- 禁渐变文字（`background-clip: text`）——评分数字用纯色分档色。
- 禁硬编码色值进组件（一律 `var(--token)`；唯二例外 `#fff`/`#000` 也不需要）。

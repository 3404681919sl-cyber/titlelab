# ADR-002: 自研 ML 核心（Float32Array 矩阵运算）替代 TensorFlow.js

## Status: Accepted (2026-10-09)

## Background

需求要求浏览器内实时训练 LR + 双隐层 MLP，数据集仅 480~500 条、特征为稀疏 TF-IDF（每样本约 40~60 个非零位、总维度约 2014）。候选方案为引入 @tensorflow/tfjs（方案 B）或自研约 200 行矩阵运算。

TF.js 的事实性劣势：完整包 gzip 约 500KB（即便按需拆 core+cpu 后端也在 160KB 级），为全部 JS 预算（40KB）的 4~12 倍；dense tensor 会把 2014 维全部物化，500 样本规模下 tensor 分配与内核调度开销大于手写稀疏循环；WebGL 后端存在设备兼容坑，CPU 后端在此规模反而更慢；layers API 对稀疏输入支持弱；训练不收敛时内部数值不可见，调试黑盒。

## Decision

自研 ML 核心：LR（全批梯度下降 + L2）、MLP（32-16 隐藏层，He 初始化，手写 Adam）、稀疏第一层前向/反向（只遍历非零特征位）、mulberry32 种子 PRNG 保证可复现。全部基于 Float32Array，集中在 src/core/，零 DOM 依赖、100% 可单测。

## Consequences

正面：包体积趋近于零；计算量与样本规模匹配（两模型合计训练 < 1s，远低于 2s 预算）；每步数值可断点调试——"浏览器内训练全过程可视化"这一产品卖点正需要这种透明度；反向传播正确性用数值梯度检验硬性把关。

负面：反向传播为最高风险手写代码——以梯度检验测试（有限差分 vs 解析梯度，相对误差 < 1e-5）+ 线性可分合成数据收敛测试（Acc ≥ 0.99）+ 黄金样例测试三重防线补偿；不支持 GPU（此规模无需）。

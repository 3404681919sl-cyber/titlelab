# ADR-005: 内置人工构建示例数据集（480~500 条，明示来源）

## Status: Accepted (2026-10-09)

## Background

零后端、零 API Key 约束下，训练数据必须随应用分发。真实平台抓取数据不可行（合规风险 + 需要后端/爬虫 + 违反零 Key 约束），且总监明确要求"不虚构真实抓取数据"。需要一种既支撑模型训练演示、又诚实标注来源的数据集构建方式。

## Decision

规模与构成：480~500 条人工构建标题，10 类目（美妆护肤/穿搭/美食/旅行/健身/学习成长/职场/家居/母婴/数码）每类约 48 条；标签 1=爆款 / 0=平淡，正负比约 4:6；约 15% 难例（有钩子词但结构散乱标 0、无钩子词但信息密度高标 1、标题党过度堆砌标 0），防止模型退化为"词表命中计数器"。

质量控制：标注口径成文于 docs/LABELING.md；构建时两轮自检（间隔 48 小时重标，分歧样本删除或改写）；运行时 schema 校验（label 合法、长度 ≤ 60 字、类目合法、正负比在 3.5:6.5~4.5:5.5 区间）fail-fast。

诚实性硬规则：titles.json 头部注释声明"人工构建示例数据集，非真实平台抓取"；UI 训练面板与页脚展示"示例数据集"徽标与说明；README 口径一致；禁止任何"基于 N 万真实笔记训练"话术，指标定位为"示例数据集上的训练表现"。

存储形态：src/data/titles.json（数据文件，不适用 300 行源码规则）+ dataset.ts 类型化加载器；随 bundle 打包（gzip 增量约 10KB），不单独发请求。

## Consequences

正面：完全离线可训练，满足零后端/零 Key；难例设计让模型必须学结构特征而非词频；诚实标注规避虚假宣传风险。

负面：示例数据集上的指标不等于真实平台预测能力——已在 UI 与文档三处明示，把"局限性"转化为"机器学习流程演示"的正确定位；500 样本是模型容量上限的主要约束（与 ADR-004 的小模型设计自洽）。
